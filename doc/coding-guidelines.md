# Coding guidelines for tdnf

tdnf is a Zig package and executable. Project-owned `.c` files, installed C
headers, shared `libtdnf*` libraries, and pkg-config metadata are forbidden.
The public package boundary is the `tdnf` module registered with
`b.addModule` in `build.zig`.

## Components

- Keep dependency direction one-way: `tools/cli` → `client` → `repomd` and
  `rpmzig` → foundational modules.
- Import another component through a Zig module registered in `build.zig`.
  Do not introduce a new component-to-component C header boundary.
- `abi/internal.zig` is a private transitional cross-module ABI. It may use
  `callconv(.c)` or `extern` declarations for internal linkage, but it is not
  installed, documented, or part of the public Zig package.
- Component-private headers are permitted only for remaining `@cImport`
  shims. Prefer replacing those imports with canonical Zig declarations.

The remaining tracked headers are private and intentionally narrow:

- `llconf/*.h` describe C-shaped exports that are still called by converted
  Zig modules and `tdnf-config`.
- `rpmzig/rpmdb.h` is the private wide rpmzig bridge still imported by the
  repository/query/transaction modules.

None is installed. New internal ABI should be declared in Zig; do not add
another compatibility header or `.inc` fragment.

## Errors and ownership

- Use typed Zig errors for new internal APIs. Preserve existing numeric
  `ERROR_TDNF_*` values where CLI behavior or tests expose them.
- Allocate into locals and transfer ownership only on success.
- Pair every allocation with an explicit cleanup path. Avoid broad catches
  and silent fallback behavior.

## Native dependencies

- Production sources must not include system RPM or Lua headers or link their
  libraries. RPM parsing, rpmdb access, verification, transactions, and Lua
  scriptlets use the native Zig modules under `rpmzig/`.
- Host `rpm`, `rpmkeys`, `rpmbuild`, and `rpmsign` are test-only fixture
  generators and behavior oracles.
- Vendored mixed-language dependencies are allowed when pinned in
  `build.zig.zon`; they must not become host development-library
  dependencies.

## Generated files

`pytests/config.json`, `pytests/mount-small-cache`, and
`bin/tdnf-automatic` are generated by `build.zig`. Edit their templates, not
generated outputs.

## Validation

Run `zig fmt` on changed Zig files and use the existing build steps:
`test`, `migration-audit`, `dead-errdefer-audit`,
`native-dependency-audit`, `public-zig-api-audit`, and
`libsolv-confinement-audit`.
