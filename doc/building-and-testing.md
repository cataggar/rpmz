# Building and testing

## Prerequisites and builds

Building requires Zig 0.17. SQLite, libsolv, TLS, and the pure-Zig Lua
runtime are pinned in `build.zig.zon`; system RPM, Lua, SQLite, and libsolv
development packages are not build dependencies. Installed-binary audits also
use `binutils`, and Python lint uses `flake8`.

Private C bindings use the exact pinned `translate-c` dependency. Each original
translation unit retains its headers and macros; libsolv remains oracle-only.
Install-prefix options and templates are generated during the maker phase,
including escaped Zig strings for prefixes containing spaces or quotes.

```sh
zig build -Doptimize=safe install --prefix ./out
zig build -Doptimize=debug install --prefix ./out
```

The install's public `bin/` directory contains only `rpmz`. Use `rpmz tdnf`
for dnf/yum-compatible commands, `rpmz repo-config` for repository
configuration, and `rpmz auto` for automatic updates. It also contains
configuration, systemd units, shell completion, and private helpers under
`libexec/rpmz`.

## Public Zig package

Consumers depend on the public `rpmz` module:

```zig
const rpmz_dep = b.dependency("rpmz", .{
    .target = target,
    .optimize = optimize,
});
exe.root_module.addImport("rpmz", rpmz_dep.module("rpmz"));
```

Use `@import("rpmz").resolver` and `.transaction_plan` for planning,
`.bundle_export`, `.transaction_bundle`, and `.bundle_reader` for bundles, and
`.replay` for exact replay. Component directories are private; there is no
public C SDK or shared library. See the
[transaction-plan API](transaction-plan-api.md),
[transaction bundle](transaction-bundle.md), and [replay API](replay-api.md).

## Tests

Run Zig unit tests with:

```sh
zig build test
zig build -Doptimize=safe test
```

Cross-check the private variadic bridge without running a foreign executable:

```sh
zig build -j2 -Dtarget=aarch64-linux-gnu common-abi-check
```

The pytest integration suite requires an RPM-aware host with `rpm`, `rpmbuild`,
`createrepo_c`, pytest, requests, and pyOpenSSL. Host RPM tools only generate
fixtures and provide behavior oracles; production does not invoke them.

```sh
zig build -Doptimize=safe install --prefix ./out
cd pytests && pytest -v
```

`zig build check` provides the install-and-pytest convenience step. Tests use
the installed private `libexec/rpmz/rpmz-test-support` bridge.

The Zig integration tests use disposable install roots and generated RPM
fixtures:

```sh
bash pytests/repo/setup-repo.sh "$(pwd)/out/repo" "$(pwd)/pytests/repo"
sudo -E zig build ztest --prefix ./out
```

Run the native helper smoke suite with:

```sh
./scripts/smoke-rpmzig.sh ./out
```

## Audits and lint

```sh
zig build docs-audit
zig build migration-audit
zig build rebrand-audit
zig build replay-docs-audit
zig build replay-confinement-audit
zig build -Doptimize=safe dead-errdefer-audit --prefix ./out
zig build -Doptimize=safe native-dependency-audit --prefix ./out
zig build -Doptimize=safe public-zig-api-audit --prefix ./out
zig build -Doptimize=safe libsolv-confinement-audit --prefix ./out
zig build lint
```

Use `-Doptimize=safe` for installed-artifact audits, as CI does. When
changing libsolv-facing code, also follow
[migration verification](migration-verification.md).

## Generated files

`pytests/config.json`, `pytests/mount-small-cache`, and `libexec/rpmz-auto`
are generated by `build.zig`. Edit their templates, not generated outputs.

## Static analysis

`ci/coverity.sh` wraps `zig build` with `cov-build` and writes its HTML report
under `build-coverity/html/`.
